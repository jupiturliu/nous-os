# Cross-Repo Release Gate

NOUS OS V2 spans multiple repositories. The release gate is a read-only readiness snapshot for public/demo releases; it must not mutate runtime state, broker state, risk config, credentials, ledgers, or live queues.

## Read-Only Checks

The default release gate checks:

- repository exists
- git status is readable
- dirty/untracked state is reported, split into `dirty_entries` (true blockers) and `dirty_allowlisted_entries` (documented noise that does not block release)
- dirty output is read with `git status --porcelain=v1 -z` so large worktrees and non-ASCII paths are not truncated or misparsed
- `dirty_count` and `dirty_allowlisted_count` expose total counts, while the entry lists show the first 50 examples
- public docs are scanned for obvious private absolute paths
- public docs are scanned for conservative secret-like tokens

Long tests are not run unless an operator explicitly passes `--run-tests`.

## Dirty Allowlist

Some paths are autogenerated routine output that writes continuously and should not block release readiness. The current allowlist:

| Repo | Allowlisted path prefix | Reason |
|---|---|---|
| `trustmem` | `agent-bus/` | Runtime queue state; visible but not a release blocker |
| `trustmem` | `data/episodes/` | Runtime episode logs and backups; visible but not a release blocker |
| `trustmem` | `knowledge/ai-infra/promoted-` | Routine promoted knowledge output from memory jobs |
| `trustmem` | `knowledge/distilled/` | Routine sediment from distillation jobs; never a release blocker |
| `trustmem` | `research/metrics/` | Runtime citation/metrics logs; visible but not a release blocker |

Allowlisted entries are still surfaced in `dirty_allowlisted_entries` so they remain visible; they just do not flip `dirty=True`. Mixing real changes with allowlisted noise correctly keeps `dirty=True` driven by the real change.

To extend the allowlist, edit `REPOS[<repo>]["dirty_allowlist"]` in `scripts/check_cross_repo_release_gate.py` and add a row above explaining the reason. Allowlisting is a release-readiness statement, not a license to skip review.

## Command

```bash
python3 scripts/check_cross_repo_release_gate.py --workspace /Users/liyao/nousos --json
```

Optional long validation:

```bash
python3 scripts/check_cross_repo_release_gate.py --workspace /Users/liyao/nousos --run-tests --json
```

## Boundary

This gate reports release readiness only. It does not authorize domain actions, broker actions, risk changes, live promotion, or runtime mutation.
